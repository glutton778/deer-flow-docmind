# 模块风险点说明（面试可口述）

> 用「一句话风险 + 触发条件 + 影响 + 应对」的结构，方便口头表达。按优先级排列。

---

## 1. 数据库持久化的「最终一致性」依赖沙箱宿主目录
- **风险**：SQLite 库写在 `/mnt/user-data/outputs/`，**只有 host 目录持久、沙箱容器本身是 `--rm` 的**。若运维不小心清空 `user-data/` 或换线程路径，库会丢。
- **影响**：结构化数据与 md 文件同生共死，未独立备份。
- **应对**：md 文件永远是兜底；需要跨文档/跨会话稳定时，用 `sandbox.mounts` 挂到统一 host 目录做平台级库，并另行定时 `cp` 备份。

## 2. 数据库写入失败被「吞掉」，可能悄然丢结构化数据
- **风险**：按需求，DB 失败**不抛错、不中断主流程**，只返回 `storage_status=failed`。
- **影响**：用户看到「任务完成」却不知其实没入库；一旦 md 被删，数据永久丢失。
- **应对**：主Agent 必须把 `failed` **显式转告用户**；建议再加一条「存储失败 → 落一份任务级失败日志/标记」，避免静默丢数据。

## 3. 写库权限依赖沙箱 UID，最容易踩坑
- **风险**：沙箱 `--cap-drop=ALL` + 以 UID1000 运行；写入 host 挂载目录需要目录权限对上（否则 `EPERM`）。
- **影响**：看起来「写成功」实际失败，或首跑就 `failed`。
- **应对**：部署笔记已给出「宿主目录 `mkdir -p` + 保证写权限 + 改动后重启 gateway」；入库脚本里也带权限失败时回退 `/tmp` 的兜底。

## 4. 超长文本截断可能截掉关键信息
- **风险**：`final_report_content` 上限 100k 字符、子输出 60k，超长即截断。
- **影响**：长文档的尾部结论/建议可能被切掉，报告与入库内容不一致（报告是全量、库是截断版）。
- **应对**：截断处加显式标记 + `warnings` 告知主Agent；告知用户「库里是截断版，全量以 md 为准」。

## 5. 三方子输出「先落盘再入库」的跨环境路径假设
- **风险**：方案假设沙箱内统一用 `/tmp/db_persist/` 与 `/mnt/user-data/outputs/`；若另一环境路径映射不同，脚本找不到文件。
- **影响**：入库失败或写入错误内容。
- **应对**：脚本对缺失文件返回空 + `warnings`；技能里显式「先确保目录存在、再落盘」；主Agent校验三份子输出非空后再调用。

## 6. doc_id 是主键，重跑/并行会冲突
- **风险**：同一 doc_id 重跑或并行写，若 `doc_source` 无 upsert 会主键冲突。
- **应对**：`doc_source` 用 `ON CONFLICT(doc_id) DO UPDATE`，`agent_intermediate` / `doc_analysis_result` 先按 doc_id 删除再插入——已做幂等。

## 7. 「多 Agent 并行 + 单点主 Agent 写库」的失控风险
- **风险**：依赖「主 Agent 一次集中写库」这一约定，但 LLM 有不确定性，可能有的子 Agent 擅自写库或主 Agent 漏调/重复调。
- **影响**：数据重复、写入侧不一致、违反「只有主Agent写」的约束。
- **应对**：把「只有主Agent可写库、子Agent禁止写库、任一子Agent失败则不写」写进系统提示词与技能「铁律」；入库脚本幂等可容忍重复调。

## 8. 「会话内提醒」与「产品化前端通知」是两个通道
- **风险**：对话内提醒是 `db_persist_skill` 返回后主Agent打印文本；前端通知是独立的消息体（`task_id/status/jump_target`）。二者需保持一致，否则前端显示的任务状态和库里实际状态不一致。
- **应对**：通知消息体以 `storage_status` / `task_status` 为准；前端拿它导航，不自行推断；状态为 `failed` 时前端也要展示「可导出 md」。

## 9. 「幻觉校验」是软约束，硬校验有限
- **风险**：`hallucination_check_flag` 由主 Agent 自评（pass/fail/unknown），非可证明的硬校验。
- **影响**：可能误判为 pass，把幻觉当结论入库。
- **应对**：标记为 `unknown` 兜底；报告与库都保留「能回溯原文」的机制（`raw_text_hash` + 结论来源可追溯），为后续人工复核留口子。

---

## 一句话总述（可作收尾）
「这套方案把结构化持久化做成**主 Agent 单点、失败不阻断、md 兜底、幂等可重跑**的轻量能力：用 SQLite + 沙箱宿主目录零配置落库，跨会话可查；风险集中在『DB 失败被软吞』『宿主目录权限』『多 Agent 是否遵守只主 Agent 写库』这几处，均已用显式提示、幂等 upsert、三层兜底（md/临时库/提示）去化解。」
